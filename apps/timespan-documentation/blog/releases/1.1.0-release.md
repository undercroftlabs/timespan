Working with dates and durations in JavaScript should be straightforward. Unfortunately, even simple operations can quickly become complicated when applications need to parse human-readable durations, calculate the difference between dates, or express an interval in different units of time.

**Timespan was created to make those operations easier.**

Today, we're introducing **Timespan 1.1.0**, the first full public release of `@undercroft/timespan`, an open-source TypeScript library for representing and working with time intervals in JavaScript.

Although the project began in 2023 and went through several early iterations, version 1.1.0 marks an important milestone: a consolidated public API, support for Node.js and browsers, improved validation, and a more complete build and testing infrastructure.

The goal is simple: provide developers with a lightweight, intuitive way to work with time without repeatedly implementing the same date and duration calculations.

## What is Timespan?

At its core, Timespan represents an interval between two dates.

A `Timespan` instance provides a consistent interface for creating, inspecting, and converting those intervals. Rather than manually subtracting timestamps and performing calculations throughout an application, developers can work with a single object.

The library supports:

- **Date intervals:** Create a timespan using a starting and ending date.
- **Human-readable duration parsing:** Convert strings such as `3d 5h 30m` into usable time intervals.
- **Unit-based construction:** Create intervals from milliseconds, seconds, minutes, hours, days, weeks, months, or years.
- **Duration conversion:** Retrieve elapsed time in a particular unit.
- **Time breakdowns:** Express an interval as a collection of years, months, weeks, days, hours, minutes, seconds, and milliseconds.
- **JavaScript and TypeScript:** Use the library in either environment, with TypeScript declarations included.
- **Browser compatibility:** Load Timespan directly using a UMD build, without requiring a bundler.

Timespan is published under the MIT license and is available through npm.

## Getting Started

Install Timespan using npm:

```shell
npm install @undercroft/timespan@1.1.0
```

Import the library into your application:

```typescript
import { Timespan } from '@undercroft/timespan';
```

### Creating an Interval Between Two Dates

The simplest way to create a timespan is to provide two JavaScript `Date` objects.

```typescript
const start = new Date('2025-04-01T00:00:00Z');
const end = new Date('2025-04-08T00:00:00Z');

const span = new Timespan(start, end);

console.log(span.toDays()); // 7
console.log(span.toHours()); // 168
```

The library calculates the interval and exposes methods for retrieving its duration in different units.

### Parsing Human-Readable Durations

Timespan also supports constructing intervals from duration strings.

```typescript
const span = Timespan.fromString('3d 5h 30m');

console.log(span.toHours()); // 77.5
console.log(span.toString()); // "3d 5h 30m"
```

This allows applications to work with duration values in a form that's easier for people to read and write.

The parser recognizes multiple units, including years, months, weeks, days, hours, minutes, seconds, and milliseconds, with supported abbreviations and aliases.

For applications that need a specific starting point, `fromString()` also accepts an optional start date:

```typescript
const start = new Date('2025-04-01T00:00:00Z');

const span = Timespan.fromString('2w 3d', start);
```

This is particularly useful when a duration needs to be interpreted relative to a specific date.

### Creating Timespans from Units

Developers can also construct timespans directly from a particular unit of time.

```typescript
const hours = Timespan.fromHours(12);
const days = Timespan.fromDays(7);
const weeks = Timespan.fromWeeks(2);
```

Alternatively, the `fromUnits()` method provides a common interface:

```typescript
const span = Timespan.fromUnits(5, 'days');
```

Each method creates a `Timespan` instance with the same conversion and inspection capabilities.

### Breaking Down a Duration

Sometimes the total number of milliseconds or hours isn't particularly useful. Applications may instead need a duration broken into individual components.

The `toTimeframe()` method provides that representation:

```typescript
const span = Timespan.fromString('1w 2d 3h');

const timeframe = span.toTimeframe();

console.log(timeframe.weeks); // 1
console.log(timeframe.days); // 2
console.log(timeframe.hours); // 3
```

This makes it easier to display human-readable durations, generate reports, or process individual time components.

## New in 1.1.0: Browser Support

One of the most significant additions in version 1.1.0 is the introduction of a **UMD distribution**.

Previously, the library was primarily packaged for module-based JavaScript applications. With this release, Timespan can also be loaded directly into a browser using a standard script tag.

```html
<script src="https://cdn.jsdelivr.net/npm/@undercroft/timespan@1.1.0/dist/index.umd.js"></script>

<script>
  const span = window.Timespan.fromDays(7);

  console.log(span.toHours()); // 168
</script>
```

The UMD build exposes `window.Timespan`, providing access to the public library API without requiring a build tool or module bundler.

This opens the door to using Timespan in static HTML pages, browser experiments, demonstrations, and existing applications that don't use modern JavaScript build pipelines.

A dedicated browser testing page was also introduced to exercise the UMD distribution and verify its public methods.

## A More Reliable Foundation

Beyond browser support, version 1.1.0 includes substantial changes to the library's internal structure and development tooling.

### A Consolidated Public API

Earlier versions exposed internal implementation details that applications could import directly.

Beginning with 1.1.0, consumers should access Timespan through the package's public entry point:

```typescript
import { Timespan } from '@undercroft/timespan';
```

The internal conversion system was reorganized into dedicated modules for constants, unit conversions, calculations, formatting, assertions, and type guards.

This separation creates a clearer boundary between the library's public interface and its implementation details, allowing internal functionality to evolve without requiring consumers to follow those changes.

**Breaking change:** Applications importing internal module paths must migrate to the public package entry point. Direct deep imports are no longer supported.

### Improved Validation and Date Handling

The release also introduces dedicated runtime assertions and validation helpers.

These include checks for invalid dates, invalid date ranges, unsupported time units, and malformed duration inputs.

Additional improvements address incorrect day calculations in certain scenarios and parsing problems involving timezones.

Together, these changes make the library more predictable when handling invalid input and calendar-sensitive calculations.

### Multiple Distribution Formats

The build infrastructure was expanded to produce distributions for different JavaScript environments.

- **ESM:** For modern module-based JavaScript applications and bundlers.
- **CommonJS:** For compatible Node.js applications.
- **UMD:** For direct browser usage through a script tag.

The release uses tsup for ESM and CommonJS builds and Rollup for the UMD distribution.

This approach allows Timespan to support multiple environments while maintaining a common public interface.

### Testing, Coverage, and Bundle Monitoring

Version 1.1.0 also expands the project's quality and release infrastructure.

Jest provides automated unit testing, while JUnit-compatible results can be generated for CI environments.

Codecov integration adds coverage reporting, and Size Limit provides visibility into the impact of changes on the distributed package.

The CI workflow includes testing across supported Node.js environments and cross-platform execution.

Build and cleanup tooling was also improved to operate more consistently across Windows and Unix-based systems.

These changes help establish a foundation for future development, where new capabilities can be introduced without losing sight of compatibility, correctness, and package size.

## Changes from Earlier Versions

Version 1.1.0 builds on work introduced during the project's earlier development.

The initial Timespan implementation dates back to May 2023, when the project established its basic duration parsing, formatting, and calculation capabilities.

Subsequent releases refined duration accuracy, improved documentation, expanded testing, and simplified the package's public interface.

The April 2025 release consolidates that work into a more complete library distribution.

In addition to the improvements described above, the 1.1.0 release:

- Removes legacy utility and calculation modules.
- Separates internal types and conversion logic into dedicated files.
- Improves cross-platform development scripts.
- Addresses dependency auditing issues involving development-only packages.
- Temporarily removes TypeDoc generation because of inconsistencies in CI.

The result is a cleaner foundation for maintaining and expanding Timespan.

## What's Next?

Version 1.1.0 establishes the starting point for Timespan as a publicly supported library.

There is still plenty of room to improve date calculations, duration handling, developer ergonomics, and compatibility across the JavaScript ecosystem.

Future development will continue to focus on keeping the library approachable while improving its capabilities and reliability.

Timespan is open source, and feedback, bug reports, and contributions are welcome.
